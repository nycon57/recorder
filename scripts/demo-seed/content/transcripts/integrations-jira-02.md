Jira sprint handoff for support-reported bugs. At the start of every sprint, engineering does a triage of all open Jira issues in the SUP project tagged customer-impacting. They sort by priority then by link-count — meaning how many Zendesk tickets are linked to a Jira issue. The more tickets linked to a single bug, the higher it gets prioritized. This is why linking correctly matters. If ten customers have the same bug but each agent created a separate Jira issue, each one has one Zendesk link and they all look low-priority. If those ten tickets are linked to a single Jira bug, it shows ten links and engineering treats it as critical. When you find that a bug you're about to escalate already has a Jira issue, do not create a new one — link your Zendesk ticket to the existing Jira issue. In the Zendesk Jira panel, use Link to existing issue. Search by the Jira issue key. The link count on the Jira side updates automatically. I'll do a monthly report showing which Jira issues have the most Zendesk links so we can push on the high-impact ones.

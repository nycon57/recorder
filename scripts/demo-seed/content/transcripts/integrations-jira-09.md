Jira project setup review — ensuring the SUP project has the right configuration for support escalations. The SUP project uses a simplified workflow: Open, In Progress, In Review, Done. Support agents only interact with Open status — everything else is owned by engineering. The SUP project has three issue types enabled: Bug, Task, and Story. Support should only create Bugs. Tasks and Stories are for internal engineering work. If you accidentally create a Task when you meant to create a Bug, you can change it in the issue type field — but do it immediately, before engineering picks it up, because the triage process is different. Custom fields that matter for support: Customer Count, which we populate with how many customers we know are affected; Zendesk Ticket Links, which auto-populates from the integration; and Customer Severity, which is our support team's assessment separate from engineering's technical severity. Customer Severity is High if the customer has explicitly said they'll churn, Medium if they're frustrated but stable, Low if it's a nice-to-have. This helps engineering weigh business impact alongside technical severity when prioritizing.
